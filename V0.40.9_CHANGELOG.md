# NEUL v0.40.9 — Future Event Auto Custom 3D

## What changed

- Every event discovered in future `/api/events` syncs now receives its own deterministic `auto-<event-id>` event layout before rendering.
- A never-before-seen venue automatically receives a conservative `runtime-<venue>` physical model, then the event receives its own layout on top of it.
- Automatic layouts now carry an explicit generation state: venue draft, ticket-source pending, official-map pending, official-map partial, or official-map verified.
- The layout stores a source/generation signature. A new seat-map URL, price rules, title/date change, or official source update marks the current event scene stale and sends it through QA again.
- A changed official seat map cannot inherit a previous `officialMapVerified` flag.
- Official-map OCR/Vision completion now updates `verifiedAgainstCurrentSource`, `seatMapNeedsRefresh`, `officialMapVerified`, and `priceMappingVerified` separately.
- Server discovery no longer treats “seat map URL + layout ID” as enough proof that a 3D scene or its Section pricing is officially verified. Final verification belongs to the client OCR/Vision QA gate.
- After OCR/Vision modifies a runtime scene, event `custom3D` metadata is recomputed immediately without requiring a reload.
- Service worker cache version bumped so deployed clients receive the new generator instead of stale v0.40.8 scripts.

## UI

No page layout or visual redesign was introduced. `index.html` and `styles.css` remain unchanged from v0.40.8.
